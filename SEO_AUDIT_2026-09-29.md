# Quicklio SEO Audit — 2026-09-29

This audit separates SEO into three operating pillars: on-page, technical, and off-page/authority. It is a working backlog, not a claim that rankings can be guaranteed.

## Executive priorities

1. Finish discovery wiring for newly launched tools, especially PDF to Word: homepage card, PDF hub card, hub ItemList entry, and menu exposure where useful.
2. Reduce crawlable homepage filter/query-state URLs such as `/?category=pdf` when a real collection hub exists.
3. Measure Core Web Vitals and indexing/canonical selection in Google Search Console instead of assuming browser QA equals search health.
4. Build authority through problem-first community participation and legitimate product launches, not backlink farming.
5. Use Search Console queries and GA4 completion events as the main feedback loop after launch.

## 1. On-page SEO audit

### What is already strong
- Tool pages use one clear H1 and one primary workflow.
- Titles, descriptions, canonicals, and sitemap coverage are enforced in CI.
- PDF to Word uses a single canonical page for close intent variants instead of thin pages for “PDF to DOCX”, “PDF to Word free”, etc.
- PDF to Word explains the real limitation: PDF is fixed-layout while Word is flowing/editable, so layout fidelity cannot be guaranteed.
- The page naturally covers selectable-text PDFs, scans/OCR, page ranges, editable DOCX, privacy/no-upload intent, and complex-layout warnings.
- Contextual related-tool links exist rather than relying only on global navigation.

### On-page work to continue
- Add PDF to Word to homepage and PDF-hub discovery so the strongest internal links point at it.
- Keep anchor text natural and descriptive; do not repeat exact-match “PDF to Word converter” everywhere.
- Add real examples/screenshots only if they make the workflow clearer; do not add decorative assets purely for SEO.
- Use actual user feedback to improve sections about tables, columns, styles, scans, legal/business documents, and post-conversion cleanup.
- Do not add FAQ blocks just to chase rich results. Google deprecated FAQ rich results for Search in May 2026; questions should exist only when they help users.

## 2. Technical SEO audit

### Current strengths
- `https://quicklio.app/` is the intended apex canonical host.
- `robots.txt` allows public crawling and declares the canonical sitemap.
- Tool pages use self-referencing canonicals.
- The sitemap lists intended canonical URLs.
- Static/browser-first architecture keeps server complexity low.
- CI already checks title uniqueness, descriptions, one H1, canonical correctness, and sitemap coverage.
- Browser QA validates mobile overflow and real product workflows.

### New technical checks added in this audit
- Sitemap URLs must be unique.
- Sitemap URLs must use HTTPS and the apex `quicklio.app` host.
- Sitemap URLs must not contain query strings or fragments.
- Indexable pages must explicitly allow `index,follow`.
- Canonical URLs must be unique across HTML pages.
- Static JSON-LD blocks must parse as valid JSON.

### Technical issues / backlog
- Google search is currently surfacing a homepage category-state URL such as `/?category=pdf`. The homepage filter state should not become a separate search landing URL when `/en/pdf/` is the real collection hub. Replace internal links to query-state variants with real hubs where hubs exist, and monitor Google-selected canonicals in Search Console.
- PDF to Word was added to the sitemap and has contextual inbound linking, but the homepage/PDF hub still need static first-class discovery entries.
- Review all heavy third-party libraries for defer/lazy-load opportunities. OCR/conversion libraries should load only when needed where practical.
- Measure Core Web Vitals from real users in Search Console. Playwright passing does not prove LCP/INP/CLS are good.
- Check the live URL with Search Console URL Inspection after each important launch and confirm Google-selected canonical matches the declared canonical.
- Keep filter/search UI states out of the sitemap and do not create indexable parameter pages without a deliberate distinct search intent.

## 3. Off-page SEO / authority audit

### Rule
Off-page SEO is not “get as many backlinks as possible.” Google explicitly treats links created primarily to manipulate rankings as link spam. Quicklio should earn mentions and links because a tool is useful.

### Reddit/community opportunities
- `r/SideProject`: viable for a transparent maker post. A recent September 2026 client-side converter launch was allowed, so this is a reasonable feedback/discovery channel.
- `r/website`: use the moderator-created self-promotion thread rather than forcing a standalone promotional post.
- `r/word`: a September 27, 2026 thread is actively discussing PDF-to-Word failure modes. Participate problem-first; explain what the converter can and cannot solve. If linking is appropriate under current rules, disclose that Quicklio is ours.
- `r/webdev`: project promotion is commonly limited to Showoff Saturday; follow the required timing/format.
- `r/InternetIsBeautiful`: deprioritize for Quicklio. Multiple 2026 submissions were removed under a “No Business Tools” rule.

### Product/maker distribution
- Product Hunt is a legitimate launch channel for Quicklio as a product, not for every tiny tool update.
- Product Hunt currently requires a new account to wait at least one week before posting and recommends joining well ahead of launch.
- Do not buy hunters, traffic, comments, or upvotes. Product Hunt explicitly warns against inauthentic launch manipulation.
- Consider a launch only after the homepage accurately represents the current product set and the strongest workflows are polished.

### Link earning ideas worth doing
- Pitch specific Quicklio tools to relevant tutorials/resource pages only when they genuinely improve the article’s workflow.
- Create original useful assets that are naturally citable: print/preflight references, conversion-quality tests, browser privacy comparisons, or practical format diagnostics.
- Contact niche educators/creators in printing, Cricut/crafts, document workflows, and small-business operations with a directly relevant tool, not a generic “please link to us” email.
- Turn repeated community problems into product improvements, then return with the solution transparently.

### Avoid
- bulk “high DR directory” packages;
- paid dofollow links/niche edits;
- automated comment/forum links;
- fake Reddit personas recommending Quicklio;
- reciprocal-link schemes;
- keyword-rich anchor campaigns;
- mass guest posts written primarily for links.

## 4. PDF to Word specific launch position

The generic keyword is highly competitive, so Quicklio should not position itself as another magical “perfect PDF to Word” clone. The product angle is:

- private/browser-local processing;
- no email/signup/watermark;
- selectable-text vs scan detection;
- optional browser-side OCR for scans;
- page-range control;
- editable-text-first DOCX output;
- honest quality diagnostics for tables/columns/complex layouts;
- clear explanation of what will need cleanup.

Recent Reddit discussion confirms that users care about broken styles, page breaks, columns, tables, scans, and documents that look correct but become unusable when edited. Product copy and future improvements should focus on those real failure modes.

## 5. Measurement

### Search Console
Monitor:
- indexing and Google-selected canonical;
- impressions and clicks;
- CTR by query/page;
- positions around 5–20;
- Core Web Vitals;
- unexpected query families;
- generative-AI and multimodal performance reports where data is available.

### GA4 / product events
Monitor:
- `tool_started`;
- `tool_completed`;
- `download_clicked`;
- `related_tool_clicked`;
- `review_submitted`;
- completion rate by landing page/source.

A page with rankings but poor completion is not a successful SEO page.
